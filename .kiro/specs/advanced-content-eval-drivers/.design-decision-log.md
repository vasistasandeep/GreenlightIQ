## Iteration 2 — doc-consistency pass (pre-tasks)

Scope: close the remaining doc-consistency findings from `.design-review.json`
(CHANGES_REQUESTED) so `requirements.md` and `design.md` state the same
normative contract. Mechanical only; no locked decision reopened (Option-(a)
full-prediction scaling with the `rounding_or_bounds_adjustment` residual-line
refinement, DETERMINISTIC_FALLBACK tier first, four default-false flags,
spec-docs-only scope all preserved).

1. **[HIGH #1] Design silently superseded the normative R5.x conservation/attribution identity by inserting the momentum term — Addressed.**
   A **requirements erratum** was added to Requirement 5 amending R5.1 (`y_log`),
   R5.2 (conservation identity), R5.4 (Attribution_Order) and the glossary
   Attribution_Order to include `ln(M_momentum)` as **Stage 2** and the
   `Franchise_Floor` as the **Stage 7** hour-space `max` clamp, with matching
   `Hours_momentum` and `Hours_franchise_floor` lines. The design.md callout was
   changed from "this design supersedes R5.x" to "aligned with R5.x as amended";
   both documents now state the same seven-term normative identity.

2. **[MEDIUM #2] Momentum_Multiplier upper clamp [1.00,1.50] was unsupported and the composition left `norm(V_trailer)` / `E_ratio` ranges undefined — Addressed.**
   `momentum_multiplier_max = Decimal("1.50")` is now a named DETERMINISTIC_FALLBACK
   coefficient in the `momentum` sub-object with a stated rationale (at saturating
   positive inputs the unclamped `raw = 1.75`, so `1.50` binds only on near-maximal
   buzz and caps a momentum-only lift at +50%). `norm(V_trailer) = clamp(V_trailer/baseline_V, 0, cap_V)`
   with `baseline_V = 1.0`, `cap_V = 2.00`, and `E_norm = clamp(E_ratio, 0, cap_E)`
   with `cap_E = 1.00` are now defined, so the formula has no free symbol. The
   formula, clamp, Hypothesis Property 3, and the explanation `bounds` string
   (`"[1.00,1.50]"`) all cite `momentum_multiplier_max` and agree.

3. **[MEDIUM #3] Churn-side attribution order called "fixed and normative" without stating the additive terms commute — Addressed.**
   The "Churn-space conservation" subsection now states the churn model is purely
   additive and its line summation **commutes**; each line (`comps_anchor`,
   per-feature points, `franchise_loyalty_credit`) is quantized to 2 dp
   (`_Q`, `ROUND_HALF_UP`) with `bounds_adjustment` the single reconciliation
   residual; and the **only** normative ordering is that `delta_C_franchise` is
   summed into the unclamped total **before** the `[0.10, 5.00]` clamp and the
   1.5 hurdle / `BORDERLINE_BAND` classification.

4. **[NIT #4] `norm(V_trailer)` referenced but undefined — Addressed.** Defined
   concretely as `clamp(V_trailer/baseline_V, 0, cap_V)` with named
   DETERMINISTIC_FALLBACK constants `baseline_V = 1.0`, `cap_V = 2.00` (see #2).

5. **[NIT #5] `release_month` neutral default was NULL with no `server_default` — Addressed.**
   The migration now adds `release_month` with explicit
   `server_default=sa.text("NULL")`, and the data-model table and input-validation
   table state NULL is the explicit neutral sentinel the resolver maps to a 1.00
   seasonality multiplier, satisfying R8.1 / R8.4.

6. **[NIT #6] Design embedded a prior review's counts in a "Responses to design review findings" section — Addressed.**
   That section was moved out of `design.md` into this dated decision log;
   `design.md` now carries only a short "Review resolution log" pointer.

## Iteration 1 — initial design review (resolved in place)

All six findings below were addressed in the design per the approved
resolutions; none required changing a locked decision.

1. **[HIGH #1] Churn-side conservation and the C_comps anchor were unspecified — Addressed.** A "Churn-space conservation" subsection (and a churn worked example) was added mirroring the hour-space discipline: `calculate_churn_mitigation` gains an optional `base_churn_override: Decimal | None` (churn analogue of `base_hours_override`) seeded with `C_comps`; the `comps_anchor` churn line strictly equals `C_comps` and never carries residual; the existing single `bounds_adjustment` entry remains the sole churn residual sink; the churn conservation identity `C_comps_anchor + Σ(feature points) + delta_C_franchise + bounds_adjustment == final` is reconciled at 2 dp; and `delta_C_franchise` is applied before the `[0.10, 5.00]` MIN/MAX clamp and the 1.5 hurdle classification. The module map moved `churn.py` into "Reused extended" to reflect the additive parameter.
2. **[HIGH #2] Franchise_Floor application was internally contradictory and collided with the Residual_Sink invariant — Addressed.** The floor is now an explicit Stage 7 in the normative order (`H7 = max(H6, Franchise_Floor)`, `d_floor = H7 - H6 >= 0`), with its own `Hours_franchise_floor` term in the conservation identity. The "flows through the `rounding_or_bounds_adjustment` sink" clause was deleted; the sink now strictly carries only quantization residual (never the structural floor offset). `H_hat` is confirmed post-floor (`H7`).
3. **[MEDIUM #3] Worked-example table dropped the momentum line the identity requires — Addressed.** The worked-example breakdown table now shows an explicit `momentum (M_momentum, neutral) | 0` row and a `franchise_floor (Stage 7, inactive) | 0` row, and the conservation sum includes the `+ 0` momentum and `+ 0` franchise-floor terms.
4. **[MEDIUM #4] `delta_C_franchise` referenced undefined symbols — Addressed.** `gamma_base = Decimal("0.15")`, `delta_order = Decimal("0.05")`, and `loyalty_signal = min(franchise_order - 1, 6)` are now formally defined, giving `delta_C_franchise = clamp(0.15 + 0.05 * min(franchise_order - 1, 6), 0.15, 0.45)` — non-decreasing in `franchise_order` and saturating at +0.45% by the 7th entry.
5. **[NIT #5] `last_updated_at` is a creation default, not an update clock — Addressed.** The Driver C seam note states that `last_updated_at` uses `created_at_column()` (creation default, no `onupdate`), so the staleness clock is valid only if the cache-writer re-stamps `last_updated_at` on every poll — a stated precondition, out of scope to implement here.
6. **[NIT #6] `PUBLIC_DOMAIN 0.95` vs "never reduces" monotonicity wording — Addressed.** Driver D notes `PUBLIC_DOMAIN = 0.95` is the single intentional sub-neutral IP multiplier (a discount, not a premium); the "never reduces below pre-modifier value" guarantee applies to premium (`>= 1.00`) modifiers only; and Hypothesis Property 3 asserts IP boundedness `[0.95, 1.25]` rather than `>= 1.00`.
